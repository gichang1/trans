# Doc Workbench · 문서 자동화 워크벤치

문서 분석, PDF 텍스트·이미지 추출, 문서 조립을 **브라우저 안에서** 처리하는 도구.
파일은 서버로 전송되지 않으며, 설치와 로그인 없이 `index.html`만 열면 동작합니다.

## 왜 하나로 묶었는가

처음 구상한 네 가지 기능은 서로 독립된 앱이 아니라 하나의 파이프라인이었습니다.

```
문서 입력 ─┬─→ [분석]  글자·단어·특수문자 통계
           ├─→ [텍스트] .txt
           ├─→ [이미지] .jpg
           └─→ [조립]  텍스트 + 이미지 → 편집 가능한 문서
```

4번은 2번과 3번의 결과를 합치는 단계이므로, 같은 추출 엔진을 공유하도록 하나의 앱에 담았습니다.

## 네 개의 모듈

**01 문서 분석** — 글자수(공백 포함·제외), 단어수, 문장수, 문단수, 한글·한자·영문·숫자·특수문자 구성비, 평균 문장 길이, 원고지 매수와 A4 예상 분량, 특수문자 종류별 집계, 자주 쓴 단어 상위 목록을 냅니다. 한글은 조사를 떼어 내고 집계하며, 숫자만 남은 토큰과 공문서 상투어는 제외합니다. 통계는 CSV로 저장할 수 있습니다.

지원 입력: `.txt` `.md` `.csv` `.docx` `.pdf` `.hwpx`

**02 텍스트 추출** — PDF에서 텍스트만 뽑아 `.txt`로 저장합니다. 좌표를 기준으로 원래 읽기 순서를 복원하고, 페이지마다 되풀이되는 머리말·꼬리말과 쪽번호를 걸러냅니다. 여러 파일을 올리면 ZIP으로 묶어 줍니다.

**03 이미지 추출** — PDF에 삽입된 그림을 원본 화질로 꺼내거나, 페이지 전체를 그림으로 렌더링합니다. 결과를 미리 보고 필요한 것만 골라 ZIP으로 받을 수 있습니다. 최소 크기 기준으로 로고나 구분선 같은 잡티 이미지를 걸러냅니다.

**04 문서 조립** — 텍스트와 그림을 동시에 꺼내 하나의 문서로 묶습니다. 그림을 원래 쪽 위치에 끼워 넣거나 본문 뒤에 모을 수 있습니다.

## 처음 아이디어에서 보완한 점

| 보완 | 이유 |
|---|---|
| 네 기능을 한 앱으로 통합 | 4번이 2·3번의 조합이라 추출 엔진을 공유하는 편이 맞음 |
| 여러 파일 일괄 처리 | 한 건씩 올리는 반복 작업을 없앰 |
| 추출 결과 미리보기 후 선택 | 필요 없는 그림까지 전부 받는 문제를 해결 |
| 머리말·꼬리말·쪽번호 제거 | PDF 텍스트를 그대로 뽑으면 쪽마다 같은 줄이 섞여 들어옴 |
| 최소 크기 필터 | 로고·구분선 같은 잡티 이미지가 수십 장씩 나오는 문제 |
| 널 문자·NBSP·소프트 하이픈 정리 | 공문서 PDF에서 흔히 섞여 들어오는 보이지 않는 문자 |
| 라이브러리를 저장소에 동봉 | 외부망이 막힌 내부망에서도 동작하도록 |
| 서버 없는 전면 로컬 처리 | 미공개 문서를 외부 서버에 올리지 않아야 함 |
| DOCX·HTML 대체 출력 | HWPX 생성 실패에 대비한 안전장치 |

## HWPX 출력에 관한 고지

HWPX는 ZIP + OWPML XML 구조의 개방형 표준이며, 이 앱은 최소 사양에 맞춰 직접 조립합니다.
생성된 파일의 **구조와 XML 적합성은 검증했으나, 한글 프로그램의 모든 버전에서 열린다는 보장은 없습니다.**
또한 HWPX 출력에는 **본문 텍스트만** 담깁니다.

그림까지 포함된 문서가 필요하면 **DOCX**를 쓰시고, 한글에서 불러오기로 여시면 됩니다.
DOCX 출력은 표준 워드 문서 파서로 열리는 것을 확인했습니다.

## 지금 할 수 없는 것

- **스캔본 PDF의 문자 인식(OCR)** — 텍스트 정보가 없는 이미지 PDF는 글자를 뽑을 수 없습니다.
- **구형 `.hwp`(한글 5.0 바이너리)** — 비공개 바이너리 형식이라 브라우저에서 열 수 없습니다. 한글에서 `.hwpx`나 `.pdf`로 저장한 뒤 올려 주세요.
- **선과 글자로 그려진 도표** — 삽입 그림이 아니므로 이미지 추출에 잡히지 않습니다. 이 경우 "페이지 전체를 그림으로" 방식을 쓰세요.

## 사용 방법

`index.html`을 브라우저로 열면 됩니다. 서버가 필요하지 않습니다.

GitHub Pages에 올리려면 저장소에 그대로 푸시하고 Settings → Pages에서 `main` 브랜치 루트를 지정하세요.

## 구성

```
index.html                  화면 구조 + 라이브러리 로더
assets/style.css            디자인 토큰과 스타일
assets/app.js               모든 처리 로직
vendor/                     동봉한 라이브러리 (내부망 대비)
  pdf.min.js, pdf.worker.min.js   PDF 해석          (pdf.js, Apache-2.0)
  jszip.min.js                    ZIP 읽기·쓰기      (JSZip, MIT/GPLv3)
  mammoth.browser.min.js          DOCX 텍스트 추출   (Mammoth, BSD-2-Clause)
```

`vendor/`의 파일을 먼저 쓰고, 없을 때만 CDN으로 넘어갑니다. 외부망이 막힌 환경에서는 동봉본으로 동작합니다.

## 색과 서체 바꾸기

`assets/style.css` 맨 위 `:root` 블록에 색·간격·서체가 모두 모여 있습니다.

```css
--accent:#6fd7ef;   /* 주 강조 */
--violet:#a78bfa;   /* 모듈 번호, 라벨 */
--bg:#0b0c0f;       /* 배경 */
```

## 검증 내역

헤드리스 Chromium에서 네 모듈을 실제로 구동해 확인했습니다.

- 01 분석 — `.txt` `.docx` `.hwpx` `.pdf` 입력 정상, 한글 조사 분리 동작
- 02 텍스트 — 3쪽 PDF에서 반복 머리말 제거 확인
- 03 이미지 — 삽입 그림 2장 추출, 40×40 잡티 이미지는 기준에 따라 제외
- 04 조립 — DOCX·HWPX·HTML·ZIP 생성, DOCX는 표준 파서로 열림(인라인 도형 2개 확인), HWPX는 구조·XML 적합성 통과
- 360px 폭에서 가로 스크롤 없음, 페이지 오류 없음

## 라이선스 고지

동봉한 라이브러리는 각자의 라이선스를 따릅니다(pdf.js: Apache-2.0, JSZip: MIT 또는 GPLv3, Mammoth: BSD-2-Clause). 배포 시 각 라이선스 조건을 확인하세요.
